# CI/CD

We defined two CI/CD pipelines for the project:
1. A workflow for automatic test execution and coverage validation.
2. A workflow for automatic version release via commit message analysis.


## Pipeline 1: Test execution

The [`ci.yml`](.github/workflows/ci.yml) workflow is called upon any `push` and `pull request` action on the `dependability` branch.

It is composed of the following steps:
- checkout of the repository;
- configures JDK 21 Temurin (the same JDK version used in the project);
- compiles the project and executes all tests via the command: `mvn -B -ntp clean verify` (the flags are used for logs cleanliness and automation);
- loads the report generated by JaCoCo on Codecov.

A fail in the pipeline stops all following steps, but a fail in Codecov loading never causes a fail in the pipeline.

## Pipeline 2: Automatic release

The [`release.yml`](.github/workflows/release.yml) workflow is called upon any `push` action on the `dependability` branch.

It is composed of the following steps:
- checkout of the repository;
- checks the summary of the commit message, the following steps are only executed if the sumary starts with one of the two preset regex:

```text
Update vX.Y.Z
Release vX.Y.Z
```

If the check was successful:
- configures JDK 21 Temurin (the same JDK version used in the project);
- builds the packages via the command: `mvn -B -DskipTests package` (the flags are used for speed and automation);
- publishes a new release on Github composed of both `webapp` and `EurekaServer` modules, with the tag: `vX.Y.Z`.
